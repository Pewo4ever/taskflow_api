# TaskFlow API

Учебный проект — REST API сервис для управления задачами команды, проектами, метками и комментариями. Проект полностью контейнеризирован с использованием Docker Compose, покрыт автотестами, логированием и включает настраиваемый CI-пайплайн на GitHub Actions.

## Технологии

- **Python 3.12**
- **FastAPI** — веб-фреймворк для создания REST API
- **PostgreSQL 16** — основная реляционная база данных
- **SQLAlchemy 2** — ORM для работы с базами данных
- **Alembic** — управление миграциями базы данных
- **Docker & Docker Compose** — контейнеризация приложения и базы данных
- **Pytest** — автоматическое тестирование
- **GitHub Actions** — CI/CD пайплайн (линтер, анализатор, тесты)

## Быстрый запуск

### Предотвращающие требования
На вашем компьютере должен быть установлен и запущен **Docker Desktop**.

### Запуск приложения
1. Склонируйте репозиторий и перейдите в папку проекта:
   ```bash
   git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ>
   cd taskflow-api
   ```

2. Создайте файл `.env` на основе примера `.env.example` (или создайте его вручную со следующими значениями):
   ```env
   POSTGRES_USER=taskflow
   POSTGRES_PASSWORD=taskflow
   POSTGRES_DB=taskflow
   DATABASE_URL=postgresql+psycopg2://taskflow:taskflow@db:5432/taskflow
   LOG_LEVEL=INFO
   ```

3. Запустите контейнеры в фоновом режиме:
   ```bash
   docker compose up --build -d
   ```

Миграции базы данных применятся автоматически при старте сервиса API.

## Логирование

В проекте настроено структурированное логирование с поддержкой всех базовых уровней (`DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`).

Уровень логирования настраивается через переменную окружения `LOG_LEVEL` в файле `.env`:
- `DEBUG` — детальная отладочная информация запросов и параметров.
- `INFO` — штатная информация о работе сервисов и успешном создании/изменении сущностей.
- `WARNING` — предупреждения о несуществующих ресурсах или некорректных параметрах.
- `ERROR` — ошибки выполнения операций с базой данных или обработка исключений.
- `CRITICAL` — критические ошибки работы компонентов системы.

Пример лога в консоли:
```text
2026-11-05 14:00:00 - app.routers.projects - INFO - Успешно создан новый проект с ID: 1
```

## Возможности API

Поддерживается полный цикл CRUD-операций (создание, чтение, чтение по ID, обновление через `PATCH` и удаление) для следующих ресурсов:

- `/v1/users` — Пользователи
- `/v1/projects` — Проекты
- `/v1/labels` — Метки
- `/v1/tasks` — Задачи
- `/v1/comments` — Комментарии к задачам

### Фильтрация данных

- Фильтрация задач по проекту и статусу:
  ```text
  GET /v1/tasks?project_id=1&status=open
  ```
- Фильтрация комментариев по задаче:
  ```text
  GET /v1/comments?task_id=1
  ```

## Примеры запросов (cURL)

Создание пользователя:
```bash
curl -X POST http://localhost:8000/v1/users \
  -H "Content-Type: application/json" \
  -d '{"email":"dev@example.com","display_name":"Разработчик"}'
```

Создание проекта:
```bash
curl -X POST http://localhost:8000/v1/projects \
  -H "Content-Type: application/json" \
  -d '{"name":"Backend TaskFlow"}'
```

## Непрерывная интеграция (CI)

В проекте настроен автоматический CI-пайплайн с помощью GitHub Actions (`.github/workflows/ci.yml`), который запускается при каждом `push` и `pull request` в ветки `main` и `master`.

Пайплайн состоит из 3-х параллельных проверок:
1. **Lint (Проверка стиля)** — проверка соблюдения стандартов кода Python через `flake8`.
2. **Analyze (Статический анализ)** — поиск потенциальных багов и уязвимостей через `ruff`.
3. **Test (Автотесты)** — автоматический запуск набора тестов через `pytest`.

## Тестирование

Тесты написаны с использованием `pytest` и выполняются изолированно.

Для запуска тестов внутри Docker контейнера:
```bash
docker compose exec api pytest -v
```

Для локального запуска (требуется установленный Python и зависимости):
```bash
pip install -r requirements.txt
pytest -v
```
